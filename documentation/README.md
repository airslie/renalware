# Website

This website is built using [Docusaurus](https://docusaurus.io/), a modern static website generator.

### Installation

Use Node.js 22 or newer (CI uses Node.js 24) and Yarn Classic 1.22.22.

```
$ yarn
```

### Dependency security

Run `yarn audit` here and at the repository root. The JavaScript Security workflow
checks both dependency trees, including build tools, and blocks HIGH/CRITICAL
findings. Lower severities remain visible in the retained reports. Audit errors,
missing summaries and unexpected exit statuses also fail the checks.

Temporary Yarn `resolutions` select patched transitive dependencies while their
parents still request older major versions:

- Application: `minimatch` 11.0.4 for ESLint and its config-array dependency.
- Documentation: `serialize-javascript` 7.1.4 for the Webpack plugins, `tinypool`
  2.1.2 for Docusaurus, and `uuid` 11.1.1 for SockJS.

Remove each override when the parent dependency supports a patched release.
Check both builds and ESLint when changing these overrides because they cross
the parents' declared version ranges.

Remaining advisories as of 3 November 2026:

- `deepmerge` (both trees): [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4).
  The latest release, 4.3.1, has no published fix. It is used by Rollup's node
  resolver and the documentation SVG tooling.
- `minimatch` (documentation): [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249).
  Docusaurus's `serve-handler` 6.1.7 requires 3.1.5 and calls its function export.
  The fixed 11.x API is not a drop-in replacement for that caller.

These findings are not suppressed. Raw `yarn audit` still exits unsuccessfully,
but CI permits these low/moderate findings under its HIGH/CRITICAL policy.
Do not downgrade `deepmerge` merely to fall
outside the advisory range, or force minimatch 11 into `serve-handler`.

### Local Development

```
$ yarn start
```

This command starts a local development server and opens up a browser window. Most changes are reflected live without having to restart the server.

### Build

```
$ yarn build
```

This command generates static content into the `build` directory and can be served using any static contents hosting service.

### Deployment

Using SSH:

```
$ USE_SSH=true yarn deploy
```

Not using SSH:

```
$ GIT_USER=<Your GitHub username> yarn deploy
```

If you are using GitHub pages for hosting, this command is a convenient way to build the website and push to the `gh-pages` branch.

### Documentation sections

- `docs/user-guide/`: day-to-day user documentation, with screenshots in
  `static/img/user-guide/`.
- `docs/technical/`: administration and technical documentation. Existing pages
  retain explicit `slug` values to preserve their published URLs; keep these when
  renaming or moving files.
- `docs/intro.md` and `docs/99-Accessibility/`: shared home and accessibility pages.

Each main section has its own sidebar. Topic folders use `_category_.json` and
`sidebar_position` to control navigation order.

### Full-text search

Search runs locally in the browser using `@easyops-cn/docusaurus-search-local`.
Its index is generated by `yarn build`; use `yarn serve` to test real search results,
not the development server. No external search account or API key is needed.
Both documentation sections are indexed. The example NHS number list is wrapped
in `search-exclude` to avoid indexing thousands of arbitrary numbers; its page
heading remains searchable. Other code examples remain indexed.

### User guide migration

The guide was imported from `rw_user_guide_v2` commit
`1f8114c32a025972e5b83193518534007709cc6e`, including all 26 topic pages,
the introduction, changelog, and 46 referenced screenshots from that repository.
The prose has not been reviewed for accuracy against the current application.
Version/changelog content is retained for a later editorial pass; Jekyll's version
variable was resolved from the source configuration, and dynamic dates were frozen
to the relevant source file's last commit date.

Jekyll front matter, image includes, callouts, and generated navigation were
converted to Docusaurus Markdown. Onboarding videos remain on Airslie.
Future guide edits should be made here so the two copies do not diverge.

`user-guide-redirects.tsv` records the old Airslie paths and their new destinations.
The Airslie site still needs those redirects and its documentation links updated
when this site is published. Cross-domain redirects must be configured on Airslie;
adding them to this Docusaurus site alone would not redirect visitors to the old host.
Check old heading fragments during that cutover. No Airslie files were changed by
this import. The existing `.app` to `.com` forwarding setup is unchanged.
